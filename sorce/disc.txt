                    CAMPUS NAVIGATION SYSTEM - ARCHITECTURE & CONNECTIONS

1. DIRECTORY STRUCTURE:
-----------------------
Campus navigation system/
├── include/                <-- HEADER FILES (.h): Interface definitions & declarations
│   ├── structure.h         <-- Core data models: Edge, Node, PathResult
│   ├── data.h              <-- Campus dataset function declarations (CampusMap, loadCampusNodes)
│   ├── graph.h             <-- Graph class declaration: Adjacency list & getNeighbors
│   ├── router.h            <-- Dijkstra shortest-path router algorithm declarations
│   └── search.h            <-- Person 3: BFS, DFS, location search, intermediate stops
│
├── sorce/                  <-- IMPLEMENTATION FILES (.cpp): Execution & business logic
│   ├── data.cpp            <-- Concrete edge weights, walking directions, and campus nodes
│   ├── graph.cpp           <-- Graph methods (buildGraph, getNeighbors, hasNode)
│   ├── router.cpp          <-- Dijkstra shortest path implementation using Graph
│   ├── search.cpp          <-- Person 3: BFS/DFS traversal, room search, intermediates
│   ├── main.cpp            <-- Terminal UI menu, CLI argument parser, runner
│   └── disc.txt            <-- Architecture & module connection guide
│
└── campus_nav.exe          <-- Compiled executable application

2. HOW THE FILES ARE CONNECTED TO EACH OTHER:
================================================================================

+------------------+         includes         +-------------------+
|   structure.h    |<-------------------------|      data.h       |
| (Edge,Node,Path) |<----+                    | (CampusMap decls) |
+------------------+     |                    +-------------------+
         ^               |                              ^
         | includes      | includes                     | includes
         |               |                              |
+------------------+     |                    +-------------------+
|     graph.h      |     |                    |     data.cpp      |
|  (Graph class)   |<----+                    | (Raw map data)    |
+------------------+     |                    +-------------------+
         ^               |                              ^
         | includes      |                              |
+------------------+     |                              |
|     router.h     |-----+                              |
|  (findShortest)  |                                    |
+------------------+                                    |
         ^                                              |
         | includes                                     | includes
         |                                              |
+---------------------------------------------------------------+
|                           main.cpp                            |
|             (Ties all headers & features together)            |
+---------------------------------------------------------------+

Summary of connections:
1. `structure.h`:
   - Defines shared structures: `Edge`, `Node`, and `PathResult`.
   - Included by `data.h`, `graph.h`, `router.h`, and `main.cpp`.
   - Uses `#ifndef STRUCTURES_H` header guard to prevent duplicate definitions.

2. `data.h` & `data.cpp`:
   - `data.h` declares `CampusMap()` and `loadCampusNodes()`.
   - `data.cpp` defines the 46 campus walkway edges and 20 landmark nodes.
   - Connected to `main.cpp` via `#include "../include/data.h"`.

3. `graph.h` & `graph.cpp`:
   - `graph.h` declares `class Graph` with `buildGraph` and `getNeighbors`.
   - `graph.cpp` constructs the adjacency map `map<int, vector<Edge>>`.
   - Connected to `main.cpp` and `router.cpp` for instant neighbor lookups.

4. `router.h` & `router.cpp`:
   - `router.h` declares `findShortestPath(...)`.
   - `router.cpp` executes Dijkstra's algorithm by querying `graph.getNeighbors(u)`.
   - Connected to `main.cpp` to calculate optimal routes.

5. `search.h` & `search.cpp` (Person 3 — Search & Traversal, DSA in C):
   - Array queue for BFS, array stack for DFS.
   - `searchLocations` linear-searches rooms by name.
   - `findIntermediateDestinations` lists nodes between two locations on a BFS hop path.

6. `main.cpp`:
   - The central entry point.
   - Includes headers from `include/`.
   - Loads data via `data.h`, builds graph via `graph.h`, routes via `router.h`,
     searches/traverses via `search.h`.

================================================================================
3. WHY HEADER GUARDS (#ifndef / #define / #endif) ARE NEEDED:
================================================================================
When `main.cpp` includes `graph.h` and `router.h`, both of those files also include
`structure.h`. Without header guards, the compiler would encounter `struct Edge`
twice in the same compilation unit and throw a "redefinition of struct" error.

#ifndef GRAPH_H    // 1. Check if GRAPH_H flag is NOT yet defined
#define GRAPH_H    // 2. Define the GRAPH_H flag immediately
// ... Declarations ...
#endif             // 3. End of guard

================================================================================
4. COMPILATION INSTRUCTIONS:
================================================================================
From the project root:
    g++ sorce/main.cpp sorce/data.cpp sorce/graph.cpp sorce/router.cpp sorce/search.cpp -o campus_nav.exe

From the sorce/ directory:
    g++ main.cpp data.cpp graph.cpp router.cpp search.cpp -o campus_nav.exe

Run:
    ./campus_nav.exe
    ./campus_nav.exe "Main Block" "Central Library"
